📘 دليل Git — add / commit / push

شرح مبسط بالتفصيل المطلق لربط مشروع CloudDevis مع GitHub

🧠 1. ما هو Git + GitHub؟

Git = برنامج يسجل التعديلات على ملفات مشروعك (مثل "حفظ باسم" لكن للمشروع كامل).

GitHub = موقع يستضيف نسخة مشروعك على الإنترنت (سحابة).

جهازك (محلي) GitHub (عن بعد) ┌────────────────────────┐ ┌──────────────────┐ │ Working Directory │ │ │ │ (الملفات على القرص) │ │ origin/main │ ├────────────────────────┤ push │ (النسخة البعيدة) │ │ Staging Area │─────────▶│ │ │ (منطقة الانتظار) │ │ │ ├────────────────────────┤ │ │ │ Local Repository │ │ │ │ (.git — المستودع │ │ │ │ المحلي) │ │ │ └────────────────────────┘ └──────────────────┘

📝 2. الأمر الأول — git add -A

git add -A

ماذا يعني حرفياً؟

  • git = برنامج Git
  • add = أضف / جهّز
  • -A = كل شيء (All)

ماذا يفعل بالضبط؟

ينقل جميع التغييرات من الملفات على القرص إلى Staging Area (منطقة الانتظار).

نوع التغييرمعناه
Modified (تعديل)غيّرت كود في ملف موجود
New (ملف جديد)أنشأت ملفًا جديدًا
Deleted (حذف)حذفت ملفًا

مثال بصري:

قبل git add -A: الملفات على القرص Staging Area ┌─────────────────┐ ┌──────────────┐ │ .gitignore MOD │ │ (فارغة) │ │ page.tsx NEW │ │ │ │ old.txt DEL │ │ │ └─────────────────┘ └──────────────┘ بعد git add -A: الملفات على القرص Staging Area ┌─────────────────┐ ┌──────────────┐ │ .gitignore MOD │──────▶│ .gitignore │ │ page.tsx NEW │──────▶│ page.tsx │ │ old.txt DEL │──────▶│ old.txt (del)│ └─────────────────┘ └──────────────┘

التحقق:

git status

الملفات الخضراء = في Staging Area، الحمراء = لم تُضف بعد.

💡 نصيحة: يمكنك إضافة ملف واحد فقط:
git add src/hooks/useEditor.ts

📦 3. الأمر الثاني — git commit -m "شرح التعديل"

git commit -m "أضفت ميزة الساعات الإضافية في الفاتورة"

ماذا يعني حرفياً؟

  • git commit = سجّل / احفظ
  • -m = message (الرسالة)
  • "..." = نص يصف التعديل

ماذا يفعل بالضبط؟

يأخذ كل ما في Staging Area ويغلّفه في صندوق يسمى commit. لكل commit:

  • 🔢 رقم فريد — مثل e1d6392
  • 📅 التاريخ والوقت
  • 👤 اسمك — مما في git config
  • 💬 رسالة تصف التعديل
  • 📸 لقطة كاملة للمشروع في تلك اللحظة

تشبيه:

git add -A = تختار البضاعة وتضعها على طاولة الانتظار git commit = تغلف البضاعة في صندوق وتلصق عليه ملصق (التاريخ + الشرح) git push = تشحن الصندوق إلى المستودع البعيد

لماذا نكتب رسالة commit؟

# بعد 6 أشهر — بدون رسائل واضحة: e1d6392 fix stuff 9db4389 update # بعد 6 أشهر — برسائل واضحة: e1d6392 أضفت ميزة الساعات الإضافية في الفاتورة 9db4389 صلحت خطأ في حساب الضريبة

عرض التاريخ:

git log --oneline

🚀 4. الأمر الثالث — git push

git push

ماذا يعني حرفياً؟

  • git push = ادفع / ارفع / أرسل

ماذا يفعل؟

يأخذ الـ commits المحلية ويرفعها إلى GitHub.

المحلي: A ── B ── C ── D (4 commits) البعيد: A ── B (commits 1 و 2 فقط) بعد git push: البعيد: A ── B ── C ── D

أول مرة فقط:

git push -u origin main
  • -u = upstream (اربط الفرع المحلي بالبعيد)
  • origin = اسم الـ remote (عنوان GitHub)
  • main = اسم الفرع
✅ بعد أول ربط:只需 git push فقط.

مخرجات الـ push:

Enumerating objects: 120, done. Counting objects: 100% (120/120), done. ... To https://github.com/Ash586/clouddevis.git e1d6392..a1b2c3d main -> main

🔄 5. الـ Workflow الكامل

مرة واحدة فقط (فعلناها ✅):

git remote add origin https://github.com/Ash586/clouddevis.git git branch -m master main git push -u origin main --force

كل يوم — بعد كل تعديل:

# 1. شوف ماذا تغير git status # 2. جهّز كل التعديلات git add -A # 3. سجّل التعديل git commit -m "وصف دقيق للتعديل" # 4. ارفع إلى GitHub git push
📌 مثال واقعي: أضفت ميزة "إجمالي الساعات":

git status ← يظهر الملفات المعدلة والجديدة
git add -A ← تجهيز كل شيء
git commit -m "أضفت ميزة حساب إجمالي الساعات" ← تسجيل
git push ← رفع إلى GitHub

❓ 6. أسئلة وأجوبة

س: هل يمكن التراجع عن commit؟
نعم: git reset --soft HEAD~1 ← يلغي آخر commit ويحتفظ بالتعديلات.
س: متى لا أستعمل --force؟
إذا كنت تعمل مع فريق. --force يعيد كتابة التاريخ ويحذف commits الآخرين.
س: هل git add -A يضيف كل شيء؟
كل شيء غير مهمَل في .gitignore. node_modules و .next و .env لا تُضاف.
س: ماذا لو أردت commit ملفًا واحدًا فقط؟
git add src/hooks/useEditor.ts
git commit -m "عدّلت الـ hooks"
git push
س: ماذا لو commit خطأ في الرسالة؟
git commit --amend -m "الرسالة الصحيحة"

📋 7. جدول اختصارات سريع

الأمرمعناهمتى تستعمله
git add -A جهّز كل التعديلات بعد الانتهاء من تعديل الكود
git commit -m "..." سجّل التعديل مع شرح بعد git add
git push ارفع التعديلات إلى GitHub بعد git commit (عندك اتصال)
git status شوف وضع الملفات قبل أي أمر للتأكد
git log --oneline شوف تاريخ التعديلات لمراجعة ماذا حدث
git pull حمّل آخر التغييرات من GitHub إذا شغلت على جهاز آخر أولاً

"يا Git، خذ الـ commits الجديدة وانقلها إلى GitHub عشان تكون في السحابة"

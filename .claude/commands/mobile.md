# Core Knowledge

## Capacitor Stack
- **Capacitor 6** wrapping a Next.js 16 static export — `output: 'export'` in next.config for mobile build
- Android WebView (Chromium-based) — CSS/JS support is high but not identical to desktop Chrome
- **Plugins in use**: `@capacitor/camera`, `@capacitor/haptics`, `@capacitor/status-bar`, `@capacitor/splash-screen`, `@capacitor/app`
- Build command: `npm run build && npx cap sync && npx cap run android`
- `capacitor.config.ts` — server URL, app ID (`com.clouddevis.app`), plugin configs

## WebView Constraints
- `position: fixed` can misbehave when virtual keyboard opens — prefer `position: sticky` for toolbars
- `100vh` is unreliable on mobile (excludes browser chrome) — use `100dvh` or `min-h-screen`
- CSS `backdrop-filter` blur works in Capacitor WebView but can cause jank on low-end devices
- `window.scrollTo()` behavior differs — test on real device, not just browser DevTools mobile emulation
- Touch events: `touchstart` fires before `click` — avoid double-fire by using `onClick` only (React handles this)

## UX Constraints for Field Workers
- **One-thumb zone**: primary actions must be reachable with right thumb — bottom half of screen
- **Glare & sun**: high contrast ratios, avoid subtle color differences that disappear in bright light
- **Data entry is painful**: minimize keyboard usage — prefer dropdowns, pickers, and smart defaults
- **Connectivity**: assume intermittent network — optimistic UI with background sync
- **Screen sizes**: test at 375px (iPhone SE), 390px (iPhone 14), 412px (Pixel 7)

## Performance
- Capacitor WebView has ~80% of desktop Chrome performance — avoid heavy animations on scroll
- Image compression before upload (already implemented in FlashFacture flow)
- Lazy-load heavy components with `dynamic()` + `ssr: false`
- Bundle size matters: every KB adds to WebView startup time

# CloudDevis Project Context

## Mobile App Structure
| Path | Purpose |
|---|---|
| `src/app/mobile/` | Mobile-specific route tree |
| `src/app/mobile/page.tsx` | Mobile home / FlashFacture entry |
| `src/components/mobile/` | Mobile-specific components |
| `capacitor.config.ts` | Capacitor configuration |
| `android/` | Native Android project (generated by Capacitor) |

## Established Mobile Patterns
- **Bottom sheet modals**: `items-end` + `rounded-t-2xl` — used in Delete modal, FlashFacture
- **Safe area**: `pb-24 md:pb-6` pattern — 24 = mobile bottom nav height + safe area
- **Mobile card list**: alternative to desktop table (see `DashboardDocumentsPanel.tsx` mobile section)
- **FAB (Floating Action Button)**: positioned bottom-right, above bottom nav
- **Touch feedback**: `active:scale-[0.97]` + `@capacitor/haptics` for button presses
- **Status bar**: dark overlay, managed in `src/app/mobile/layout.tsx`

## FlashFacture Flow (Core Mobile Feature)
The mobile document creation wizard — critical path. Key files:
- Company guard (redirect if no company set up)
- Smart-morph CTA (changes based on context)
- Client dock (inline client search/create)
- Exit guard (unsaved changes warning)
- Autosave to localStorage
- Success bottom sheet with share/PDF options

## Known Issues to Watch
- Keyboard pushes up fixed bottom nav — handled with `KeyboardWillShow` listener
- Camera plugin requires `CAMERA` permission in AndroidManifest
- `npx cap sync` must be run after every dependency change that affects plugins

# Response Guidelines

1. **Always specify if a solution is web-only or requires a native Capacitor plugin**
2. **Test assumptions against real mobile behavior** — note when a CSS property behaves differently in WebView
3. **Reference the safe area and bottom nav patterns** from existing mobile components
4. **For new screens**, start with the mobile layout constraints (44px targets, bottom-reachable CTAs) before styling
5. **Flag battery/memory impact** for features that run in the background or poll frequently
